# 03-3 アカウントUI

参照：[03-3](https://app.notion.com/p/3f4df60d2114810aae7fcf7f9a6eab72)、[06](https://app.notion.com/p/3f3df60d21148181a499ee7a4448f9a1)。

2026-10-11の依頼に合わせ、メール・パスワード入力に代えてGoogle／X／ゲスト参加のUIを実装。実認証は06、戦績取得は12で接続する。Notionの内容は変更していない。

- `AppHeader`を全画面で使用。タイトル専用だった高さ・アカウントボタンのCSSを共通化。
- `AuthPanel`：PCは紹介＋選択カード、720px以下は縦並び。Google／Xは800msの仮処理後にタイトルへ。処理中は二重操作を防ぎ、アンマウント時にタイマーを解除。
- `AccountPanel`：仮プロフィール、レート、試合数、戦績リンク、ログアウト。
- `HistoryPanel`：サンプル戦績と今回の結果、戦績なしの状態。
- `#/auth`は未ログインなら入口、ログイン後はアカウント。タイトルと見出しも切り替える。
- 仮ログインは外部通信・永続化を行わず、ログアウト／再読み込みでリセット。
- 開発時のみ「表示確認用」からログイン失敗・戦績なしを再現可能。失敗のチェックを外して再試行すると成功。入力欄を廃止したため入力エラーは対象外。

## 確認

最新mainを基点に `npm run check`（Prettier、Lint、Vitest 27件、型チェック・ビルド）成功。ブラウザでGoogle／Xの仮ログイン、処理中、失敗と再試行、ゲスト参加（Enter操作）、アカウント／戦績／空状態、ログアウトを確認。1280px・390pxでレイアウト確認、390pxで横はみ出しなし。確認画像：`account-ui-desktop.jpg`。OSのダークモード切替による実機表示は未確認（今回の画面は固定配色）。

## 06で接続するもの

Firebaseのプロバイダー設定と実際のGoogle／Xログイン、ログアウト、認証状態の監視、本人確認、ゲスト識別。仮認証の状態を本人確認には使わない。プロバイダーのキャンセル・通信失敗をUIのエラー状態に接続する。実運用前にプロバイダーの公式ブランド素材・ボタン要件に合わせる。

## 文言・初回ヘッダーの調整

指定のキャッチコピー、初回向け説明、UIプレビューの注記を削除。初回（`session.entered === false`）はヘッダーのアカウントリンクを表示しない。タイトルへ戻る操作は従来どおり参加済みのみ。遊び方を開いた際の「元の画面に戻る」は残す。ゲスト参加／ログイン後はアカウント導線を表示し、ログアウトすると再び非表示になる。
