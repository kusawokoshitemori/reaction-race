## 起動

06と同じFirebase・DB設定を使う。`backend/.env` に `APP_ORIGIN=http://localhost:5173` を追加し、Goを再起動する。ブラウザを127.0.0.1で開く場合は `http://127.0.0.1:5173` と完全一致させる（末尾スラッシュなし）。未設定時はWebSocketを拒否する。本番は公開HTTPSオリジンを指定し、同一オリジンの `/api/lobby` をWebSocket対応プロキシでGoへ転送する。

Viteの `/api` プロキシはWebSocket対応。確認用の別バックエンドを使う場合は `API_PROXY_TARGET=http://127.0.0.1:8081 npm run dev -- --port 5174` のように指定できる。その場合 `APP_ORIGIN` も5174に合わせる。

## 通信

1. Firebase IDトークンを付けて `POST /api/ws-ticket`。401の場合フロントは一度だけ更新トークンで再試行。
2. `GET /api/lobby?ticket=...` をWebSocketへUpgrade。`Tickets.UpgradeGuard` がOrigin、有効期限30秒、一回限りの消費を検査。チケットはアプリ処理前にURLから除去。
3. 10秒以内に `{"type":"join"}` を送る。UID・名前・ルームIDはクライアントから受け取らない。接続時の本人情報とDBの表示名を使用。
4. サーバーが `room` スナップショットを送る。
5. `{"type":"leave"}` で退出。画面移動・ログアウト時にも送信して接続を閉じる。

```json
{"type":"room","roomId":"uuid","phase":"waiting","deadline":1791979200000,"serverTime":1791979190000,"capacity":100,"participants":[{"id":"opaque-uuid","name":"ゲスト","bot":false,"guest":true}]}
```

時刻はUnixミリ秒。画面の残り秒はサーバー通知の差分と受信後の単調時計から計算。0秒表示だけでクライアントが参加者を確定することはない。Firebase UIDは他参加者へ公開しない。

## 参加・確定・切断

- 最初の参加から10秒（暫定）。100人に達したら即確定。待機枠はサーバーが自動割り当てする。
- 確定時に不足人数分のボットを一度だけ追加し、`phase: locked` の100人一覧を通知。後続参加者は別ルームへ。
- 同じUIDの有効な接続は1つ。別タブは1008 `already_connected` で拒否。電波断などで旧接続が残る場合も拒否し、旧接続のpong期限（最大約45秒）まで待って再試行するよう案内する。新しい接続で旧接続を置き換えない。待機締切を過ぎる可能性があり、08で試合中の復帰方針を決める際に再検討する。
- 待機中の切断は退出。最後の人が退出した空ルームはタイマーごと削除。
- 確定後の切断は一覧を変更しない。新しいチケットで再接続すると同じ確定一覧を取得。明示的退出はUIDの所属を解除するが確定一覧は保持。
- 08がまだないため確定後2分でルームを破棄する。08では試合終了時に `Manager.Finish` を呼び、保持期限も試合ライフサイクルに合わせて変更する。
- 全管理操作とタイマーはmutexで直列化。送信は接続ごとに1 writer。最新の完全スナップショットへ集約し、遅いクライアントで他ルームを止めない。
- メッセージ上限1KiB、書込期限5秒、ping間隔15秒、pong期限45秒。初回join期限10秒。参加中UID上限10000、保持ルーム上限1000。
- プロセス終了でタイマー・接続を閉じる。メモリ状態は再起動で失われる。チケット・ルームは単一プロセス用。

## 08との接続点

`Manager.Roster(roomID)` は確定した100人のコピーを返す。`GenerateBotInputs` はそのうちボットだけにサーバー基準の入力時刻を生成する。暫定分布は通常92%（合図後180〜900ms）、フライング5%（開始〜合図前）、未入力3%。入力は時刻順で各ボット最大1件。乱数生成器を注入でき、テストで再現可能。

08は合図時刻を決めた後、生成した入力を通常入力と同じ受付処理へ渡す。今回の07では合図、入力受付、判定、結果・レート更新を実行しない。画面も参加者確定までを表示し、従来のローカル仮試合へ自動移行しない。既存GamePanelは08で接続するため保持。

## ログ

`lobby joined / locked / left / reconnected / removed` にroom_idと必要な人数・公開participant_idを記録。トークン、チケットURL、Firebase UID、表示名は記録しない。リバースプロキシでもクエリ付きURLをアクセスログへ残さない。
