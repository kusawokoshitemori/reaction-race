## HTTP

全APIはFirebase IDトークン必須。レスポンスは `Cache-Control: no-store`。

- `GET /api/me/history?offset=0`: 登録ユーザー本人の戦績。終了日時降順、同時刻は試合ID降順。
  20件ずつ `entries` と `hasMore` を返す。offsetは0〜1,000,000。
- `GET /api/matches/{id}`: 保存済み試合の参加者一覧。参加した登録ユーザーだけ閲覧可能。
  存在しない試合と他人の試合は共に404。順位昇順、順位なしは末尾。
  試合当時の表示名・補正後時間・結果区分・レート前後を返す。
- `GET /api/ranking`: 匿名認証でも閲覧可能。保存済み試合がある登録ユーザーを
  現在レート降順、同レート内は内部ユーザーID順で最大50人返す。
  同レートは競技順位（1、1、3）。表示名は現在値。本人は `self` で識別する。
  `id` はこの応答内の行番号。Firebase UIDは公開しない。

ゲスト・BOTはランキング対象外。ゲストの履歴閲覧は403。
保存待ち・保存失敗中の試合は一覧に出ない。DBで保存完了したデータだけを使い、
ルームのメモリ保持期間やサーバー再起動に依存しない。
DB障害は503、サーバーログ `saved results read failed` に対象リソースと安全化したエラーを記録。
取得は5秒でタイムアウトする。

## UI

既存の `#/history` 内で一覧→詳細→一覧へ遷移する。詳細を閉じても一覧ページを保つ。
`#/ranking` の既存パネルへ実データを接続。読み込み中・空・失敗・再試行を表示。
401時はトークンを一度更新する。10秒タイムアウトと画面破棄時のキャンセルを設け、
古いユーザー・ページの応答を表示しない。
オフセット方式なので閲覧中に新しい試合が保存されるとページ境界が動く場合がある。
詳細のURL共有、任意ユーザーの履歴公開、トップ画面の仮レート・試合数置換は本変更の範囲外。
