# 切断・復帰（TASK-27）

仕様: https://app.notion.com/p/3f3df60d211481d6aad1eca1d87df7dc

## 作業分解と実装

- 接続管理: 待機中の切断は退出。locked以降は明示的な退出でも参加者・最初の入力を保持し、試合を続行する。
- 復帰プロトコル: サーバー起動ごとのUUIDをsnapshotのinstanceIdとして配信。joinにinstanceIdとroomIdを指定すると認証済みUIDの所属を検証して復帰する。IDは権限の代わりにはならない。
- UI: 切断時は入力を止め、再試行ボタンで新しいチケットを取得して再接続。現在のフェーズ・受付済み入力・確定結果を表示する。タップは自動再送しない。
- 再読込: locked以降の復帰先をユーザー別sessionStorageに保持。#/gameと#/resultの再読込時は認証完了後に復帰する。ストレージ利用不可の場合は同じ画面内の再試行のみ保証する。
- 再起動: 起動IDが異なる場合はserver_restartedで拒否し、試合中止を表示。ユーザーが「新しい試合に参加」を押すまで新規参加しない。
- 期限切れ: 同じ起動IDでも所属が消えていればroom_expired。既存の終了後保持期間（2分）を超えた結果のDB取得は後続の永続化タスク。

## 複数タブと入力

1ユーザー1接続。既存接続を優先し、後続タブはalready_connectedで拒否する。回線断の検出前には元の接続が残るため、最大45秒程度待って再試行する場合がある。復帰先はタブ単位のsessionStorageに保存し、他タブの値を上書きしない。

復帰時にも同一参加者IDを使用する。旧接続からの入力は無効、採用済み入力は再送されても不変。結果表示後は接続のみ閉じ、保持期限内の再読込を可能にする。「再戦」では復帰情報を消し、終了済み所属から新しい待機室へ参加する。

通常のサーバー終了時は接続へ中止通知を返す。強制終了による再起動は、接続できるようになった後の復帰要求で判定する。停止中に再起動と一時的なネットワーク障害を断定しない。メモリのみの構成であり、複数プロセスへの負荷分散には未対応。

## ログ・検証

既存のlobby joined / reconnected / leftとmatchの状態遷移ログでroom_id、match_id、participant_idを追跡する。再起動による復帰拒否もroom_idとreasonを記録する。認証トークンは記録しない。

Goのrecovery_test.goで各フェーズの復帰、入力不変性、重複接続、結果復元、新規参加、再起動、期限切れ、所属検証を確認。既存の実WebSocketテストで待機中退出・二重接続拒否・試合完了を確認する。フロントのLobbyPanelテストで再接続・再読込時の復帰要求、受付済み入力の抑止、再起動／期限切れの案内を確認する。

手動確認: ゲーム中にネットワークを切断して再試行する、同じ画面を再読込する、別タブで同じユーザーとして参加する、ゲーム中にGoを再起動して再試行する。結果画面の再読込と再戦も確認する。
